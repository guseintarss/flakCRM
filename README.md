# flakCRM — сеть бизнесов

Один развёрнутый сервис для нескольких бизнесов: у каждого своя CRM, свой сайт,
свой каталог и свои заявки. Рестораны, сервисные компании и объекты размещения
работают на общем коде, но в полностью изолированных базах данных.

```
Гость → публичный сайт /s/<slug> → заявка → лид в CRM бизнеса
Владелец → кабинет → конструктор сайта → публикация → заявки → CRM
```

## Что уже работает

- **Мультитенантный кабинет.** Один аккаунт может владеть несколькими бизнесами
  и переключаться между ними. Чужие бизнесы недоступны: доступ проверяется по
  членству и отдельной базе.
- **Три вертикали:** ресторан, сервисный бизнес, туризм и размещение. Вертикаль
  задаёт подписи, поля каталога и форму заявки.
- **Конструктор сайта:** профиль, фирменный цвет, обложка, каталог и публикация.
  Черновик публично недоступен.
- **Публичный сайт:** меню/услуги/номера и форма заявки. Бронь столика для
  ресторана — дата, время, число гостей, имя и телефон.
- **Заявки в CRM:** каждая заявка создаёт лид с источником `website`. Статус
  заявки — это статус лида, отдельной рассинхронизированной сущности нет.
- **Базовая CRM:** компании, контакты, лиды, сделки, задачи, активности,
  дашборд, поиск и CSV-экспорт.
- **Демо-стенд:** четыре настроенных бизнеса и один аккаунт владельца.

## Стек

- Node.js **22.13+** (используется встроенный `node:sqlite`), Express 5.
- React 19, Vite, React Router, TanStack Query.
- SQLite: центральный реестр + отдельный файл БД на каждый бизнес.
- Валидация Zod, пароли на `scrypt`, сессии в HttpOnly cookie.

Внешняя БД, Redis, очередь и облачные сервисы не требуются.

## Быстрый старт

```bash
npm install
npm run dev
```

- Кабинет и публичные страницы в dev: <http://127.0.0.1:5173>
- API: <http://127.0.0.1:3001>
- Демо-вход: `owner@flakcrm.ru` / `demo12345`

В dev демо создаётся автоматически. В production демо по умолчанию **не**
создаётся, чтобы не оставлять известный пароль на реальном стенде.

Демо-бизнесы:

| Адрес | Вертикаль |
| --- | --- |
| `/s/tihiy-dvorik` | Ресторан |
| `/s/chayhana-nal` | Ресторан — второе заведение с другим меню и оформлением |
| `/s/gorservice` | Сервисный бизнес |
| `/s/gostevoy-dom-elbrus` | Туризм и размещение |

Два ресторана в демо показывают главный сценарий: одно и то же приложение
обслуживает несколько бизнесов одной вертикали, каждый настроен отдельно.

Команда `npm run db:seed` идемпотентно добавляет демо-аккаунт и четыре бизнеса в
уже существующий реестр. Существующие демо-бизнесы не перезаписываются.

## Production

```bash
npm ci
npm run build

NODE_ENV=production \
HOST=0.0.0.0 \
PORT=3001 \
DATA_DIR=/var/lib/flakcrm \
COOKIE_SECURE=true \
npm start
```

`npm start` запускает Express, который раздаёт собранный `dist/`, API и публичные
сайты. Для демонстрационного стенда добавьте `SEED_DEMO=true` или выполните
`npm run db:seed`.

Требования к эксплуатации:

- HTTPS завершается на reverse proxy; приложение слушает HTTP.
- `COOKIE_SECURE=true` обязателен для HTTPS, иначе браузер не отправит cookie.
- Один процесс Node на один каталог `DATA_DIR`. SQLite в режиме WAL не
  предназначен для нескольких приложений или сетевой ФС.
- Каталог данных содержит персональные данные гостей: ограничьте доступ ОС,
  делайте резервные копии и не публикуйте файлы БД.

### Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Интерфейс прослушивания |
| `PORT` | `3001` | Порт приложения |
| `DATA_DIR` | `./data` | Каталог данных |
| `REGISTRY_PATH` | `$DATA_DIR/registry.db` | Реестр аккаунтов, бизнесов и сессий |
| `TENANTS_DIR` | `$DATA_DIR/tenants` | Базы бизнесов |
| `WORKSPACE_TIMEZONE` | `Europe/Moscow` | Часовой пояс отображения |
| `BASE_CURRENCY` | `RUB` | Валюта CRM |
| `SEED_DEMO` | `true` в dev, `false` в prod | Создавать демо-данные при старте |
| `COOKIE_SECURE` | `false` | Флаг `Secure` у сессионной cookie |

`DATABASE_PATH`, `WORKSPACE_NAME`, `LOCAL_USER_NAME` и `LOCAL_USER_EMAIL`
относятся к старому однопользовательскому режиму и тестовому `createApp`. Сетевой
сервер их не использует. Старая база `data/flakcrm.db` не изменяется.

## Данные и резервные копии

```
data/
├── registry.db          # аккаунты, бизнесы, членство, сессии
└── tenants/
    ├── tenant-<hash>.db # CRM, каталог и заявки одного бизнеса
    └── ...
```

- Реестр и каждая база бизнеса — отдельные SQLite-файлы с WAL.
- Для согласованной копии остановите сервер и скопируйте весь `DATA_DIR`
  вместе с `-wal` и `-shm`; либо используйте `sqlite3 ... ".backup"`.
- Не переименовывайте файлы бизнесов вручную: путь хранится в реестре.
- Для переноса стенда копируйте реестр и каталог `tenants` вместе.

## Тесты

```bash
npm test
```

Покрыты:

- регистрация, cookie-сессия, Bearer-токен, отсутствие секретов в ответах;
- изоляция компаний и настроек между двумя бизнесами;
- публикация сайта, черновик, публичная заявка и связь со статусом лида;
- создание второго бизнеса, переключение и запрет доступа к чужому tenant.

Дополнительно проверяются `typecheck`, ESLint и production-сборка.

## Ограничения текущего MVP

- Нет сброса пароля, приглашений сотрудников, ролей кроме владельца и 2FA.
- Нет биллинга, тарифов и самостоятельного удаления бизнеса.
- Вертикаль фиксируется при создании бизнеса; название, адрес и каталог
  редактируются.
- Нет загрузки изображений: обложка и фото задаются URL.
- Нет email/SMS-уведомлений и онлайн-оплаты.
- Список заявок показывает последние 200; пагинации пока нет.
- Публичные сайты живут по пути `/s/<slug>`, без собственных доменов.
- Публичные страницы — SPA без SSR: SEO-индексация ограничена.
- Rate limit входа хранится в памяти процесса и сбрасывается при рестарте.
- Все открытые базы бизнесов кешируются в процессе; для сотен активных
  бизнесов понадобится LRU-вытеснение.
- Docker-конфигурация не входит в проект и не проверялась.

## Структура

```
server/
├── index.ts              # запуск сетевого приложения
├── config.ts             # окружение
├── app.ts                # старый createApp и общие middleware
├── network/
│   ├── app.ts            # сборка мультитенантного Express
│   ├── registry.ts       # аккаунты, бизнесы, членство, сессии
│   ├── tenant.ts         # ленивое открытие БД и AsyncLocalStorage
│   ├── provision.ts      # создание бизнеса
│   ├── auth.ts           # регистрация, вход, переключение
│   ├── site.ts           # сайт, каталог, заявки → лиды
│   ├── builder.ts        # API конструктора
│   ├── public.ts         # публичный API
│   ├── schemas.ts        # Zod-схемы сети
│   └── demo.ts           # демо-аккаунт и демо-бизнесы
├── routes/               # CRM API /api/v1
└── tests/                # интеграционные тесты
src/
├── pages/                # кабинет, конструктор, публичный сайт, вход
├── components/           # оболочка, переключатель бизнесов, UI
├── lib/session.tsx       # сессия и активный бизнес
└── api/network.ts        # клиент сети
shared/                   # общие контракты клиента и сервера
```
